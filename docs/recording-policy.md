# スピーチ・面接の録音方針

決定日: 2026-09-07。ユーザー承認済み。対象はB〜A級の学習者によるスピーチ・面接の音声入力であり、教材の配布音声とは区別する。方針の確定は機能の実装・検証完了を意味しない。実装状況は `delivery-plan.md` を参照する。

## 利用目的と入力

- 面接は「音声質問 → 音声回答」と「音声質問 → 筆記回答」を別の練習として提供する。以下の録音・認識の規定は音声回答にだけ適用し、筆記回答ではマイク・音声認識権限を要求しない。
- 面接官の質問は端末内のインドネシア語音声合成を暫定利用する。質問の日本語訳はユーザー操作で開くヒントに限定し、自動表示しない。
- 話した内容を文字起こしし、内容・構成・文法・語彙を評価する。
- 発音・抑揚・流暢さは評価対象外。文字起こしだけからこれらを推定して採点しない。
- 利用目的、音声の一時保存と削除、テキスト送信先、評価対象を録音開始前に説明する。
- ユーザーが開始操作をした時点でマイク権限を要求し、認識APIに必要な権限も処理する。拒否・制限・利用不可を区別する。
- 音声認識は端末内に限定する。端末・言語・認識モデルが非対応の場合は理由を表示し、クラウド音声認識へ自動で切り替えない。

## 音声の保存と削除

| 項目 | 確定方針 |
| --- | --- |
| 保存先 | アプリ専用の一時ファイル。バックアップ対象外 |
| 提出前 | 再生・録り直しができる。録り直し時に旧音声を削除する |
| 通常削除 | 提出・破棄・課題終了時に削除する。採点無効時の確認済みテキスト保存でも削除する。送信失敗後の再評価にはテキストだけを使う |
| 異常終了 | 残存音声は次回起動時、課題を開く前に削除する |
| 外部送信 | 音声ファイル・音声参照URLは送らない |

異常終了後の削除は次回起動に依存するため、起動していない間の時間指定削除は保証しない。
削除失敗を成功扱いにせず、再試行可能な状態を持つ。起動時の残存音声削除が完了するまで新しい録音課題を開始しない。

## 提出・採点・再評価

- 文字起こしを利用者が確認してから提出する。自動送信しない。
- 確認済みテキスト、設問、採点に必要な識別子と版情報のみを既存の採点中継サーバー経由でClaudeへ送る。
- 中継サーバーの非保存とClaude側の保持条件は別に扱う。音声由来テキストの実送信開始前に、利用アカウントの保持設定・適用条件を確認し、説明に反映する。これはローカル録音・認識・モック実装を止める条件ではない。
- 未送信・再評価待ちの文字起こしは端末に保存し、再送と削除を可能にする。音声は再評価キューに残さない。
- テキストは利用者が削除するまで保持し、課題画面の破棄と設定の学習データ削除の両方で削除できる。
- 音声認識失敗や採点失敗を不正解・0点として扱わない。
- 音声、文字起こし、回答本文をログに出さない。
- 発話課題用の設問・ルーブリック・基準回答を用意する。既存作文の基準を、課題種別を書き換えて流用しない。
- 面接は各回答を確認・採点してから掘り下げへ進む。最大3回答を1トピックとして保持し、各回の提出ID・設問・回答・採点結果を保存する。掘り下げの評価には同じトピックの過去の確認済み回答だけを文脈として添える。音声は各回答の提出時に削除する。合否にかかわらず全文と結果は課題の破棄・設定のデータ削除で消せる。

## 実装の受入条件

### 外部保持条件の確認メモ（2026-09-08）

[Anthropicの商用API保持説明](https://privacy.claude.com/en/articles/7996866-how-long-do-you-store-my-organization-s-data)では、標準の入力・出力は30日以内に削除されるが、別契約、規約違反対応、法令等による例外がある。これは本アプリが使う組織・ワークスペースの契約確認を代替しない。

利用者が確認する場所は、[公式ZDR説明](https://privacy.claude.com/en/articles/8956058-i-have-a-zero-data-retention-agreement-with-anthropic-what-products-does-it-apply-to)にあるClaude Platformの `Settings > Privacy Controls > Data retention period`。使用するキーの所属組織とワークスペース、モデル固有の条件も照合する。キーそのものは共有不要。適用条件が未確認の間は、実ユーザーの音声由来テキストを送信しない。

### 動作確認

- 権限拒否・端末内認識非対応で録音開始やクラウド認識への切替が起きない。
- 録音、停止、再生、録り直し、確認、提出、破棄の状態遷移を持ち、二重開始・二重提出を防ぐ。
- 音声中断や画面離脱で録音を停止し、課題終了時には削除する。
- 提出・破棄・終了・録り直し・次回起動の各経路で音声削除を検証し、削除失敗も扱う。
- リクエストと再評価キューに音声データ・音声参照を含めない。
- スピーチ・面接を有効にする前に、端末内認識、マイク権限、音声中断を実機で確認する。
